# 业务容量与数据配额需求可行性分析

分析日期：2026-10-13。本文为需求与架构分析，未修改业务代码；建议方案不是已经确认的产品规则。

## 能力目标与结论

为合同、客户、问盘、跟进单、发票提供按租户管理的存储容量和数据条数配额。用户可以查看用量、独立导出或清理文字及文件、购买扩容包；系统严格阻止超额写入，自动清理超过 24 小时未关联业务的上传文件，并按阈值告警。

五项需求均有技术可行性。整体属于跨前端、业务后端、文件服务、订单服务及后台任务的改造。当前前端仓库足以确认部分复用入口，不能据此确认外部后端已有配额、文件引用或通知能力，也不能承诺完整排期。

- `apps/web-h5/app/components/payment/Fps.tsx` 对接 `/pms-resource/web-back/minio/upload`；代码表明存在外部文件上传入口，但未核实其服务实现和存储配置。
- `apps/web-admin/src/pages/package-edit/package-model.ts` 已支持套餐数量、附加服务及展示说明，`capacityLabel` 是文案，不能作为真实容量限额。
- `apps/web-h5/app/[locale]/my-orders/AddService.tsx` 已有增值服务购买入口，可扩展扩容商品；后端权益发放、支付确认和计费规则仍需核实。
- `apps/web-admin/src/pages/RolesPage.tsx` 当前显示静态角色数据；未找到 Owen 专属权限实现。该平台管理页也不能代表外部业务系统的角色能力。
- 本仓库未找到覆盖上述五类业务的完整 CRUD、配额拦截、文件引用登记和容量告警实现。实施前需取得真实业务后端及对应业务前端的信息。

## 固定需求与建议规则

| 范围     | 用户要求                           | 实现建议与约束                                                       |
| -------- | ---------------------------------- | -------------------------------------------------------------------- |
| 上传     | 前端检测大小，超限不发上传请求     | 所有上传入口复用校验；服务端再次验证真实大小和租户剩余容量           |
| 数据新增 | 达到条数上限则阻止写入             | 新增、批量导入、复制、恢复、后台及集成入口统一执行配额检查           |
| 导出     | 文字与文件分别下载                 | 文字导出 CSV/XLSX，附件导出 ZIP；格式待确认，二者用业务 ID 对应      |
| 清理     | 文字与文件分别清理                 | 分开预览影响、执行任务和核算释放量；关联文件不能因删除单条引用而误删 |
| 权限     | Owen 角色管控                      | 明确是否指 Owner；服务端按租户校验导出、删文字、删文件、加购权限     |
| 扩容     | 增加 GB 时同步增加条数             | 使用版本化商品规则，订单保存权益快照；付款确认后只生效一次           |
| 满载     | 严格阻止超额并引导加购             | 不允许依赖前端缓存作最终判定；仍提供查询、导出、清理和加购入口       |
| 孤立文件 | 上传超过 24 小时且无业务引用则清理 | 文件登记、统一引用表、定时任务和删除前再次确认；排除受保护文件       |
| 告警     | 80%、90%、100% 分级反馈            | 阈值按真实用量计算；存储和条数分别显示，通知去重、失败重试           |

## 关键不变量与生命周期

### 严格限额必须覆盖并发

文件申请上传时预占容量，上传完成后按实际大小结算；失败、取消或过期释放预占。判定原则为“已用字节 + 已预占字节 + 本次申请字节 ≤ 有效容量”。

数据条数判定为“已用条数 + 本次新增条数 ≤ 有效上限”。配额扣减和业务新增在同一事务中完成；跨服务时需等效的预占与补偿机制。不能先查询计数再无条件插入，否则并发会突破上限。MySQL 可用事务中的锁定读取保护计数更新，见 [MySQL 锁定读取说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。

恰好写到上限可成功；已达到上限后拒绝继续增加相应资源。如果条数满了是否同时禁止给现有记录上传附件，属于待确认的跨资源阻断规则。

### 清理与释放配额必须一致

文字删除成功后可按确认的计数规则释放条数；文件删除确认成功后释放字节。后台任务未完成时显示“清理中”和预计释放量，不能提前承诺已回收容量。失败任务需要重试且不能重复扣减。

删除文字但保留文件时，文件必须进入明确的保留或待清理状态，不能意外被 24 小时任务删除；仅删除附件时保留业务记录，界面显示附件已清理。如果多个记录共享附件，最后一个引用解除后才可按规则删除对象。

“恢复容量”解释为恢复可用额度，不默认包含误删恢复功能。若引入回收站，需另定保留期、存储计费和恢复时的配额检查规则。

### 孤立文件清理需要可靠的引用证据

建议文件状态为：上传中、已上传待关联、已关联、保留、删除中、已删除。24 小时从服务端确认上传完成计时；仅对待关联且无有效业务引用的文件执行清理。

后台任务领取文件和业务绑定必须互斥，绑定不得接纳正在删除的文件。存量附件须先回填引用并完成核对，再启用自动删除；引用核对失败时跳过删除并重试。

单凭对象创建时间不能判断业务孤立。若采用 S3 兼容存储，可另行评估未完成分片清理；AWS 文档明确该规则处理的是未完成分片上传，不能替代业务引用判断，见 [未完成分片清理说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpu-abort-incomplete-mpu-lifecycle-config.html)。实际存储服务能力仍需核实。

### 扩容与告警需要稳定状态

扩容商品建议显式保存增加字节数、各业务增加条数、有效期和价格。订单完成后原子增加权益，重复支付回调不重复发放。扩容到期导致超额时，建议保留已有数据，阻止增加受限资源，并允许导出、清理和续购；该处理方式待产品确认。

90% 登录弹窗的“30 日内不提示”建议按用户与租户保存到服务端，只屏蔽该弹窗，不屏蔽容量 BAR、满载阻断或邮件。

90% 和 100% 邮件分别记录发送事件，由后台任务处理重试。建议每租户、每指标、每告警周期只生成一次事件；何时重置周期、直接跨越两个阈值是否合并邮件需确认。外部邮件发送须使用稳定事件 ID；能否避免发送超时后的重复投递取决于邮件服务能力。

付款凭证属于扩容必要流程。满载时仍须允许受控上传凭证，使用独立配额、单文件上限及身份校验；订单引用须纳入受保护引用，不能被业务孤立清理任务误删。

## 接口与数据模型建议

- 配额查询：返回租户、有效上限、已用、预占、可用、各业务计数和告警状态；前端上传或清理后刷新。
- 上传申请、完成、取消：返回文件 ID、实际字节、状态；服务端校验租户身份、大小和关联资格。
- 业务创建：事务内校验条数；对超单文件、容量不足、条数不足、权限不足返回不同错误码和用户提示。
- 清理预览与执行：分别提供文字和文件操作，返回任务 ID、影响记录、可释放条数或字节、失败项。
- 导出创建与查询：分文字和文件任务，租户隔离、受控下载、下载有效期；导出临时文件使用独立资源预算和清理规则。
- 扩容订单：使用原有购买流程，新增容量商品及权益快照；服务端支付确认驱动权益生效。
- 告警偏好：保存 90% 弹窗免打扰截止时间；邮件事件不与浏览器本地存储绑定。

建议持久化租户配额、用量计数、配额预占、文件元数据、业务文件引用、扩容权益、通知事件、用户免打扰和任务审计。新增表及字段必须遵守实际业务后端的迁移流程。

## 实施前必须明确的产品决定

1. Owen 是 Owner（租户拥有者）、现有自定义角色还是指定人员？平台管理员与租户管理员分别有哪些权限？
2. 配额按公司、租户、账号还是产品计费？GB 采用十进制还是二进制？单文件上限是多少？
3. 条数仅限客户，还是五类业务各有限额或共用池？草稿、归档、软删除、明细和重复数据如何计数？
4. “文字”是否仅指数据库记录？数据库占用、缩略图、文件版本、备份及待关联上传是否计入容量？
5. 删文字保留附件时保留多久？是否需要回收站？存量客户超限如何过渡？
6. 每个扩容包增加哪些业务条数？有效期是否跟主套餐一致？到期、降级及退款如何调整权益？
7. 邮件收件人是谁？“一次”按终身、账期还是一次超限周期？条数是否同样触发 80/90/100% 告警？
8. 实际业务前端、CRUD 服务、文件服务、身份权限和邮件服务分别由哪个项目维护？

## 交付顺序与验收

第一阶段：确认计费口径及真实服务边界，完成存量用量盘点、文件引用回填和商品规则。

第二阶段：上线服务端配额与上传预占、前端统一大小校验、容量及条数 BAR、严格阻断和扩容闭环。

第三阶段：上线文字/文件独立导出清理、24 小时孤立清理、分级通知及用量核对任务。

最低验收场景：超单文件不发上传请求；只剩一个名额时并发创建最多成功一次；多文件并发不超容量；批量导入按确定规则拦截；重复支付回调只增加一次权益；清理失败不错误释放容量；文件绑定与清理并发不误删；90% 免打扰跨设备生效；100% 仍严格阻断；满载用户可完成加购凭证上传；租户不能查看或清理其他租户文件；存量受保护附件不被自动删除。

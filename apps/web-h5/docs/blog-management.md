# 博客内容管理

前台 `/blog` 和 `/blog/:slug` 读取 MySQL 中的发布快照。后台 `web-admin` 的「博客管理」（`/blog`）管理文章、分类、页面文案。正文与预览复用操作手册的安全富文本渲染器、编辑器和图片上传入口。

## 发布与编辑

先新增并发布分类，再创建文章。保存只更新草稿，预览使用管理员接口重新读取的已保存草稿；点击发布后才更新公开快照、分类、排序、搜索字段及标签关联。页面设置同样需要保存后发布。首次发布后文章 slug 永久锁定，下架不解锁。

已发布文章或分类必须先下架才能删除。删除分类同时检查草稿与发布版引用。下架分类会隐藏其公开文章，重新发布分类后恢复。管理员并发操作使用版本号及事务锁，冲突时保留本地输入，需重新载入后处理。

文章可配置标题、摘要、分类、标签、封面及替代文字、展示日期、阅读分钟数、精选和排序。页首大卡片取当前页首篇；只有被后台指定精选的文章带精选标记。顺序为精选优先、排序升序、展示日期降序、ID 降序。

## 接口与查询

- `GET/POST /api/admin/blog`：现有平台管理员认证；带版本的新增、保存、发布、下架、删除。后台通过 `/h5-hook` 代理访问。
- `GET /api/blog?categoryId=1&q=租約&page=1`：公开分类、页面文案、当前页摘要、总数和查询参数，每页固定 12 篇；响应不包含正文和草稿。
- `GET /api/blog/:slug`：已发布文章、页面文案及排除当前文章后的前三篇相关文章。文章或分类未发布时返回 404。
- 搜索范围为发布标题、摘要及标签。标签按 NFKC、首尾空白和小写规范化去重；标签查询使用规范化名称。LIKE 参数转义 `%`、`_` 和 `!`，不会把用户输入当通配符。首版不搜索正文或使用全文索引。
- 客户端搜索防抖 200ms；筛选和页码同步 URL，保留产品参数，过期请求取消，失败保留当前内容并提供重试。
- 所有博客接口禁止 HTTP 缓存，公开读取只做请求内去重；发布后重新验证博客布局。

## 数据库与索引

迁移 `0009_blog_content.sql` 仅新增五张博客表，所有字段和表都有注释，不修改手册及平台表。需要 MySQL 8.0+，以支持明确的降序索引和 `utf8mb4_0900_bin` 排序规则。

| 索引                                                      | 用途                                  |
| --------------------------------------------------------- | ------------------------------------- |
| `uk_blog_article_slug`                                    | slug 唯一性及详情定位                 |
| `idx_blog_public_order`                                   | 已发布列表及精选／排序／日期／ID 顺序 |
| `idx_blog_category_order`                                 | 发布分类筛选及同一排序                |
| `idx_blog_admin_state`                                    | 管理发布状态、更新时间和 ID 查询      |
| `uk_blog_tag_name`                                        | 规范化标签名称去重                    |
| 关联表主键 `(article_id, tag_id)`、`idx_blog_tag_article` | 发布标签替换及按标签反查              |

公开列表在同一只读事务内读取已发布分类，再按其 ID 查询文章，以避免分类联表改变排序索引的执行计划。文章分类、标题、摘要、精选、排序、展示日期及标签关联只在发布时同步。普通 B-tree 索引不能加速包含匹配，不应将关键词搜索描述为已使用全文索引。

## 202 部署顺序

以下命令在仓库根目录运行，复用应用的运行时配置及数据库连接，不在命令或代码中硬编码业务地址或凭证。

```bash
pnpm --filter web-h5 exec tsx migrate.ts --check
pnpm --filter web-h5 db:migrate
pnpm --filter web-h5 db:seed:blog
pnpm --filter web-h5 exec tsx scripts/check-blog.mts
```

先迁移、初始化，再发布应用。初始化以设置单例为事务标记，仅首次导入四个分类、六篇文章、原配图及页面文案；重复执行不覆盖后台编辑，也不复活已删除文章。数据库缺表或读取失败时前台显示错误和重试，不返回静态内容。`check-blog.mts` 只读检查字段注释和执行计划；小数据量时优化器可能选择全表扫描，应结合真实数据量评估。

## 验证

```bash
pnpm --filter @go-tech/blog-content test
pnpm --filter web-h5 exec vitest run lib/blog app/api/admin/blog 'app/[locale]/blog'
pnpm --filter web-admin exec vitest run src/pages/blog src/pages/manual
```

真实 MySQL 集成测试为显式启用，使用 `BLOG_TEST_DATABASE_URL` 指定**允许创建和删除专用测试库**的测试实例连接，设置 `BLOG_MYSQL_TEST=1` 后运行 `lib/blog/mysql.integration.test.ts`。测试只在随机生成的 `codex_blog_test_*` 数据库执行迁移、种子、发布及 EXPLAIN，结束时删除该数据库；不使用业务库作为写测试目标。建议在临时 MySQL 8 实例执行，不扩大 202 业务账号权限。连接串通过本机环境传入，不提交到仓库。
